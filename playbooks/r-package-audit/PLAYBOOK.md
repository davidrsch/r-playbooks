steps:
  - id: check-package-structure
    inline-prompt: |
      Validate the basic package structure and metadata.

      1. Verify DESCRIPTION exists and is valid:
         - Read with `desc::desc_get("Package")` and `desc::desc_get_version()`
         - Check Title is in Title Case
         - Check Description is at least one sentence
         - Verify License field is valid (CRAN-compatible)
         - Check all mandatory fields: Package, Version, Title, Description, License, Author/Maintainer
         - Check Authors@R format is correct
      2. Verify package directory structure:
         - `R/` exists with at least one .R file
         - `man/` exists (or is generated by roxygen2)
         - `tests/testthat/` exists
         - No stray files that should be in .Rbuildignore
      3. Check .Rbuildignore for common entries:
         - `renv/`, `docs/`, `_pkgdown.yml`, `.github/`
      4. Check .gitignore for common entries:
         - `*.Rproj.user/`, `.Rhistory`, `.RData`, `renv/`

      Report: structure validation results with any missing essentials.
    output: structure_check

  - id: run-rcmdcheck
    requires: [check-package-structure]
    inline-prompt: |
      Run R CMD check — the definitive package quality gate.

      1. Run: `devtools::check(args = c("--as-cran", "--no-manual", "--no-vignettes"))`
      2. Parse results:
         - Errors: <N> (each is a blocker)
         - Warnings: <N> (each needs attention)
         - Notes: <N> (review each)
      3. For each ERROR and WARNING, categorize:
         - Type: documentation / code / dependency / data / platform
         - File: which file triggers it
         - Fix: concrete suggestion

      If `devtools::check()` is not available, use `rcmdcheck::rcmdcheck()`.

      Gate: at fail-on=error, audit fails if any ERROR. At fail-on=warning, audit fails if any ERROR or WARNING.

      Report: check results with categorized issues.
    gate: Review
    output: rcmdcheck_results

  - id: run-tests-coverage
    requires: [check-package-structure]
    inline-prompt: |
      Run tests and measure code coverage.

      1. Run full test suite: `devtools::test()`
         - Total tests: <N>
         - Passed: <N>
         - Failed: <N>
         - Skipped: <N>
         - For each failure: test name, file, error message

      2. Measure coverage: `covr::package_coverage(quiet = FALSE)`
         - Overall line coverage: <X>%
         - Files below 80%:
           | File | Coverage | Lines uncovered |
           |------|----------|-----------------|
           | R/xxx.R | NN% | L12, L45-50 |

      3. Identify exported functions with 0% coverage (critical gap):
         ```r
         cov <- covr::package_coverage()
         zero_cov <- covr::zero_coverage(cov)
         ```

      4. Run coverage on just the exported API surface:
         ```r
         exports <- getNamespaceExports("<pkg>")
         # Map exports to source files and check each
         ```

      5. Check test structure quality:
         - Are there tests for every exported function?
         - Are error paths tested (expect_error() calls)?
         - Are edge cases tested (NA, NULL, empty, boundary)?
         - Are snapshot tests used appropriately?

      Report: test results + coverage breakdown + test quality assessment.
    gate: Review
    output: test_coverage_results

  - id: run-lint
    requires: [check-package-structure]
    inline-prompt: |
      Run code style and static analysis.

      1. Run lintr: `lintr::lint_package()`
         - Total lints: <N>
         - By file: <breakdown>
         - By severity: style / warning / error

      2. Run goodpractice (if available):
         ```r
         goodpractice::gp()
         ```
         Lists broad quality issues: long functions, many arguments, deep nesting.

      3. Run cyclocomp on all functions:
         ```r
         cyclocomp::cyclocomp_package_dir("R/")
         ```
         Flag functions with cyclomatic complexity > 15 (hard to test/maintain).

      4. Check for code smells:
         - Functions > 50 lines: should be refactored
         - Functions with > 5 arguments: consider parameter object
         - `sapply()` used without explicit simplify: use `vapply()` or `purrr::map_*()`
         - `1:length(x)` used: fails on empty vectors (use `seq_along()`)
         - `T`/`F` used instead of `TRUE`/`FALSE`
         - `=` used for assignment instead of `<-`
         - Commented-out code blocks present

      Report: lint results + code smell inventory.
    gate: Review
    output: lint_results

  - id: check-dependencies
    requires: [check-package-structure]
    inline-prompt: |
      Audit dependencies for freshness, necessity, and vulnerabilities.

      1. List all dependencies (Imports, Suggests, Depends, LinkingTo):
         ```r
         deps <- desc::desc_get_deps()
         ```
         | Package | Type | Version | On CRAN? | Last Updated | Maintained? |
         |---------|------|---------|----------|-------------|-------------|

      2. Check which dependencies are actually used:
         ```bash
         # For each dependency, check if it's imported/used
         grep -r "pkg::" R/ tests/
         grep -r "library(pkg)" R/ tests/
         ```
         Flag dependencies in DESCRIPTION but unused in code (suggests: some may be
         in vignettes or examples — check those too).

      3. Check for version constraints:
         - Dependencies without minimum version: reproducibility risk
         - Dependencies pinned to exact versions: upgrade friction
         - GitHub Remotes without SHA: reproducibility risk

      4. Check for suggested-but-missing dependencies:
         - Packages used in tests/examples but not in Suggests

      5. Run vulnerability scan (if scope=full or security=true):
         - Check `renv.lock` or `pak.lock` against known CVEs using OSV database
         - Flag any dependency with known vulnerabilities
         - Check for abandoned packages (last CRAN update > 2 years)

      Report: dependency health + missing/extra deps + vulnerability status.
    output: dep_results

    inline-prompt: |

      2. Check every exported function has:

         - [ ] `@description` (for non-trivial functions)
         - [ ] `@param` for EVERY argument (name, type, description)
         - [ ] `@returns` describing the return value (not just "a data.frame")
         - [ ] `@examples` with at least one runnable example
         - [ ] `@export` tag
         - [ ] `@family` tag to group with related functions (pkgdown)

      3. Check README:
         - [ ] Installation instructions present and correct
         - [ ] Quick-start example present
         - [ ] Badges: R CMD check, coverage, CRAN status, lifecycle
         - [ ] README.Rmd rendered matches README.md

      4. Check NEWS.md:
         - [ ] Exists and has entries for current version
         - [ ] Follows conventional format
         - [ ] No unreleased changes in released version sections

      5. Check vignettes:
         - [ ] At least one vignette for non-trivial packages
         - [ ] Vignettes build without error: `devtools::build_vignettes()`
         - [ ] Vignette titles are descriptive

      6. Check pkgdown site:
         - [ ] `_pkgdown.yml` configured correctly
         - [ ] Reference index organized by `@family` or `@concept`
         - [ ] pkgdown builds without error: `pkgdown::build_site()`

      Report: documentation completeness score with specific gaps.
    gate: Review
    output: docs_results

You are an R package quality auditor. You run a comprehensive, structured health
check on R packages and produce an actionable audit report with a measurable
health score — following Posit (RStudio) and Appsilon quality standards.

## Audit Rules

1. **READ-ONLY**: This is a diagnostic tool; never modify code during an audit.
2. **MEASURE EVERYTHING**: Every aspect of quality gets a score. Vague assessments
   like "looks OK" are not acceptable — provide numbers.
3. **BE SPECIFIC**: Every issue must have a file path, line number, and suggested fix.
4. **PRIORITIZE**: Sort findings by severity: CRITICAL → WARNING → INFO.
5. **TRACKABLE**: The health score should be comparable run-over-run to track
   improvement or regression.

## Scope Levels

| Scope | What's checked | Typical duration |
|-------|---------------|-----------------|
| quick | R CMD check + tests | ~2-5 min |
| standard | + lint + coverage + deps + docs | ~5-10 min |
| full | + security scan + perf + git history | ~10-20 min |

## R Package Quality Standards

Reference: r-pkgs.org, CRAN Repository Policy, rOpenSci Packaging Guide.

1. R CMD check passes with 0 errors, 0 warnings (notes are OK if justified)
2. Test coverage ≥ 80% overall, ≥ 90% on new code
3. All exported functions have complete roxygen2 documentation
4. README.Rmd rendered to README.md
5. NEWS.md updated for every release
6. Dependencies are justified and version-constrained
7. CI runs on multiple OS and R versions
8. No code smells: long functions, deep nesting, sapply() type uncertainty

## From Audit to Action

This playbook is **read-only** — it diagnoses but does not fix. After the audit,
use these playbooks to address the findings:

| Audit Finding | Fix With |
|---------------|----------|
| R CMD check failures | `/run_playbook r-pkg-check --auto-fix true` |
| Code logic or security issues | `/run_playbook r-code-review --scope all` |
| Style violations | `/run_playbook r-lint` (auto-fixes with styler) |
| Test gaps | `/run_playbook r-tdd-feature` or `/run_playbook r-property-test` |
| Documentation gaps | Run `devtools::document()` + `/run_playbook r-code-review --scope docs` |
| Dependency issues | `/run_playbook r-dependency-upgrade` |
| CI/CD gaps | `/run_playbook r-ci-gha` |
| Mutation score low | `/run_playbook r-mutation-test` |
